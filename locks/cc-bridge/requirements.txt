# harness/locks/cc-bridge/requirements.txt
#
# Resolved versions for harness/services/cc-bridge, whose requirements.txt
# declares six dependencies with floating lower bounds and carried no
# lockfile. A range does not resolve to a version, so a vulnerability
# database had nothing to match against and the dependency scanner
# reported on a surface it could not resolve rather than failing:
# C-GAP-FLOATING-PYTHON-SPECS-UNRESOLVABLE.
#
# Named requirements.txt in its own directory because that is the only
# filename trivy's pip analyzer recognises. A .lock extension parses as
# nothing and the instrument reports zero findings over a file it cannot
# read, which is worse than the absent scanner it replaces: a clean result
# and an unreadable subject are indistinguishable downstream.
#
# Generated from a venv built against the declared specs, not hand-written.
# The service's own requirements.txt stays the declaration of intent.
